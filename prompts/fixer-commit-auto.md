1. Never stage or commit a path listed in {RUN_DIR}/uncommitted.txt or under "Files changed during the review". When a fix falls into such a file, apply it, leave the file uncommitted, and report the fix as `applied, not committed: the user's uncommitted edits` or `applied, not committed: changed during the review`. A fix is committed whole or not at all: when any file a fix changes is such a path, apply every file of the fix, commit none of them, and report the whole fix as `applied, not committed: …`. Before your first edit of any file, run `git status --porcelain --untracked-files=all -- <file>`: if the file already differs from HEAD or is untracked, the user has been editing it since the review started — treat it exactly like a path listed in {RUN_DIR}/uncommitted.txt: apply the fix, commit nothing of that fix, and report `applied, not committed: the user's uncommitted edits`.
2. Apply every fix first, then decide what to commit. A file changed by any fix that stays uncommitted is committed by no fix: `git commit --only` takes a file's whole content, the uncommitted fix's change with it. So every fix that also changes such a file is applied and reported `applied, not committed: shares <file> with an uncommitted fix`, and its own files in turn are committed by no fix; repeat until no fix changes its mark.
3. Only then write the commit message, for the fixes still marked `done`, in this repository's style; when no fix is left marked `done`, write none and commit nothing. Read `git log -n 20 --format='%s%n%n%b'`: follow its subject convention (for example `fix(scope): …`), and if its commits carry bodies, add one that says why, one line per fix still marked `done`. Do not mention the review, the reviewers, or herdr-review. Add no trailers or attribution lines after the body — no `Co-Authored-By:`, `Claude-Session:` or "Generated with …" line — even where the history has them. Write the message to {RUN_DIR}/fix-auto-commit.txt. Start the file with the subject line, with no blank line before it, and never start the subject with `#`, which git can strip as a comment.
4. Commit once, with only the files of the fixes still marked `done`: stage them (`git add <file> …`), then commit exactly those paths:
   `git commit --only -F {RUN_DIR}/fix-auto-commit.txt -- <file> …`
   `--only` commits exactly the named paths and disregards anything staged for other paths, so work the user had already staged never enters the commit.
   Do not push.

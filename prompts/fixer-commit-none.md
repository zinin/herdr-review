Commit nothing. The change under review is uncommitted work, so a fix committed on its own could leave HEAD without the code it builds on, failing its own tests. Stage nothing (no `git add`), commit nothing, and do not push. Report each fix you apply as `applied, not committed: the review covers uncommitted work`; the report's commit line is `no commit`. This says only how an applied fix is reported. The Rules above still hold: a fix that would delete, move or rename a path listed in {RUN_DIR}/uncommitted.txt — in this scope, the change itself — is not applied, and is reported `skipped: <path> holds the user's uncommitted work; left to the user`.

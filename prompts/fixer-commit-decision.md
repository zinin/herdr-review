1. Never stage or commit a path listed in {RUN_DIR}/uncommitted.txt or under "Files changed during the review". When the decision falls into such a file, apply it, leave the file uncommitted, and report `applied, not committed: the user's uncommitted edits` or `applied, not committed: changed during the review`. The decision is committed whole or not at all: when any file it changes is such a path, apply every file, commit none of them, and report `applied, not committed: …`. Before your first edit of any file, run `git status --porcelain --untracked-files=all -- <file>`: if the file already differs from HEAD or is untracked, the user has been editing it since the review started — treat it exactly like a path listed in {RUN_DIR}/uncommitted.txt: apply the decision, commit nothing, and report `applied, not committed: the user's uncommitted edits`.
2. Write the commit message in this repository's style. Read `git log -n 20 --format='%s%n%n%b'`: follow its subject convention (for example `fix(scope): …`), and if its commits carry bodies, add one that says what was wrong and why the change fixes it. Do not mention the review, the reviewers, or herdr-review. Add no trailers or attribution lines after the body — no `Co-Authored-By:`, `Claude-Session:` or "Generated with …" line — even where the history has them. Write the message to {RUN_DIR}/fix-<ORCHESTRATOR: n>-commit.txt. Start the file with the subject line, with no blank line before it, and never start the subject with `#`, which git can strip as a comment.
3. Stage only the files you changed when you report `done` (`git add <file> …`), then commit exactly those paths:
   `git commit --only -F {RUN_DIR}/fix-<ORCHESTRATOR: n>-commit.txt -- <file> …`
   `--only` commits exactly the named paths and disregards anything staged for other paths, so work the user had already staged never enters the commit.
   Do not push.
